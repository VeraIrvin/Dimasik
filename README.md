# Историко-генеалогический портал Дмитрия Воробьева

Интерактивная карта **76 губерний** Российской империи по историческому срезу **1897 года**. Изначально десять опубликованных губерний выделены бежевым, перечислены в постоянном окне поверх карты и доступны по клику; остальные видимы как бледный контекст. Администратор может публиковать другие губернии. Next.js, TypeScript и MapLibre GL JS; без Mapbox и современных тайлов. Картографические данные загружаются из локальных GeoJSON.

## Запуск

```sh
npm install
npm run dev
```

Откройте `http://localhost:3000`. Для production-сборки: `npm run build && npm run start`. Скрипты `predev` и `prebuild` копируют локальные worker-модули MapLibre из установленной версии пакета в `public/maplibre/`; сгенерированные файлы не редактируются вручную.

## Вход администратора

Перед локальным запуском создайте `.env.local` по структуре `.env.example`: задайте уникальные `ADMIN_USERNAME` и `ADMIN_PASSWORD`, а `ADMIN_SESSION_SECRET` заполните случайной строкой не короче 32 символов (например, результатом `openssl rand -hex 32`). Env-файлы с рабочими значениями игнорируются Git; для развёртывания все три значения задаются в окружении сервера. Если логин или пароль не настроены, вход закрыт. Кнопка «Вход» открывает модальное окно на главной странице; сессия подписана серверным секретом и хранится в HttpOnly-cookie до 8 часов. После входа администратор остаётся на карте: в конце списка доступных губерний появляется «+ Добавить губернию». Выбор неопубликованной губернии и свободного slug публикует её на карте и открывает страницу всем посетителям. На странице опубликованной губернии администратор может изменить slug и описание либо удалить публикацию после подтверждения. Удаление скрывает страницу и очищает её описание, но не удаляет исторический полигон с карты.

## Исторические границы и атрибуция

**Источник главной карты:** Ivan Sablin, Aleksandr Kuchinskiy, Aleksandr Korobeinikov, Sergey Mikhaylov, Oleg Kudinov, Yana Kitaeva, Pavel Aleksandrov, Maria Zimina, [*Transcultural Empire: Geographic Information System of the 1897 and 1926 General Censuses in the Russian Empire and Soviet Union*](https://doi.org/10.11588/DATA/10064), heiDATA, [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Для главной карты использован **только** исторический слой `1897RussianEmpire.shp` (WGS84 / EPSG:4326), без данных переписи 1926 года. Описание авторов называет это ГИС-реконструкцией на основе переписи 1897 года; среди картографических источников также указан атлас Ильина 1914 года. Поэтому карта не претендует на точность архивной межевой съёмки на конкретный день.

- `public/data/gubernias.geojson` — все **76 губерний** (Polygon/MultiPolygon), отобранных по точному названию `NAMERUS` из слоя 1897 года. Геометрии взяты из одного источника; добавлены `id`, `name`, точки подписей `labelCoordinates` и пороги показа `labelMinZoom`. Поля `published` и `slug` в файле задают **исходные** десять публикаций при отсутствии отдельного состояния; после первой административной операции актуальный список задаётся файлом `data/gubernia-publications.json`.
- `public/data/empire-context-1897.geojson` — остальные **23** территориальные единицы исходного слоя (области и иные территории, не губернии). Они образуют нейтральный исторический силуэт без границ, подписей и кликов; они не выдаются за губернии.

**Источник карты уездов на страницах губерний:** Gijs Kessler и Andrei Markevich, [*Electronic Repository of Russian Historical Statistics (RiStat), Russian Empire Historical GIS Maps (1897)*](https://doi.org/10.34894/NQOASN), Version I (2020), DataverseNL. Оригинальные файлы `Russian Empire 1897 - Districts` и `Russian Empire 1897 - Provinces` содержат границы второго и первого уровней одного исторического среза 1897 года (EPSG:4326). На каждой странице **контур губернии и границы уездов/округов взяты только из этих двух файлов RiStat**; геометрия главной карты Sablin и др. поверх них не накладывается. Это две независимые реконструкции одного года, поэтому их линии могут не совпадать: например, RiStat относит Закатальский округ к Тифлисской губернии, а её Эстляндская губерния (на главной карте — Ревельская) не включает часть западных островов. Эти расхождения не исправляются вымышленными контурами.

В карточке набора DataverseNL указано CC0 с требованием ссылки на RiStat, тогда как [общая страница правил RiStat](https://ristat.org/how-cite) указывает CC BY-NC-SA 4.0. Источник приведён здесь и на странице «О проекте» (под картой отдельной строки атрибуции нет); перед публичным коммерческим использованием или дальнейшим распространением геоданных следует уточнить применимые условия у правообладателя.

При замене исторического среза заменяйте **оба файла главной карты** согласованными геометриями одного периода, сохраняя стабильные `properties.id/name` для губерний и начальные `published/slug`. Если набор `id` изменится, мигрируйте файл состояния публикаций `data/gubernia-publications.json` вместе с геометрией; несовпадающий набор будет отклонён. `labelCoordinates: [долгота, широта]` — внутренняя точка, рассчитанная по контуру в проекции Web Mercator. `labelMinZoom` определяет порог показа подписей нейтральных губерний; пересчитывайте эти поля при замене геометрии или текста. Уездные карты при смене периода пересоздавайте из одного согласованного набора границ губерний и уездов соответствующего года; современные административные границы не подмешивайте.

`public/data/uyezds-1897/<id губернии>.geojson` — 76 локальных файлов с контуром губернии и её административными единицами второго уровня (703 объекта для этих губерний), преобразованных из оригинальных GeoPackage RiStat. Каждый файл содержит один `kind: "province"` и набор `kind: "district"` с `id`, `name` и `provinceId`; названия уездов и округов оставлены как в историческом источнике. Генератор `scripts/generate-uyezds-1897.py` принимает **оба** оригинальных GeoPackage в качестве аргументов, проверяет их опубликованные SHA-1 и строго сопоставляет названия с 76 `id` из `public/data/gubernias.geojson`. Официальный архив можно получить по [API DataverseNL](https://dataverse.nl/api/access/datafiles/578935,578936); после распаковки выполните `python3 scripts/generate-uyezds-1897.py "/путь/Russian Empire 1897 - Districts" "/путь/Russian Empire 1897 - Provinces"` для обновления локальных файлов. Скрипт не допускает отсутствующих губерний и не создаёт приблизительных границ.

`app/api/gubernias/route.ts` отдаёт все 76 исторических полигонов с актуальными признаками публикации (`GET`) и публикует выбранную губернию (`POST`); `app/api/gubernias/[id]/route.ts` изменяет slug/описание (`PATCH`) или снимает публикацию (`DELETE`). Изменяющие запросы требуют серверной сессии администратора. Данные о публикациях хранятся отдельно от геометрии в `data/gubernia-publications.json` (создаётся при первом изменении, игнорируется Git). Путь можно задать `GUBERNIAS_STATE_PATH`. Файл требует постоянного записываемого диска и **одного** серверного процесса: параллельные процессы не синхронизируют записи. Для публичной эксплуатации понадобятся постоянное общее хранилище, управление секретами и замена демонстрационных учётных данных.

## Сообщения губернии

На `/guberniya/[slug]` опубликованные сообщения видны всем посетителям; слева расположен список заголовков с переходом к соответствующему сообщению. У администратора форма «Новое сообщение» изначально свёрнута. Заголовок сообщения может содержать до 1000 символов. Категория обязательна при создании и редактировании; доступные значения задаются в «Настройках» — по умолчанию «Статья», «Персона», «Ссылка на источник» и «Источник с индексацией». Старые сообщения без категории продолжают отображаться, но при редактировании требуют её выбрать. Редактор TipTap поддерживает начертания, заголовки, списки, цитаты, цвет, ссылки и выравнивание; сообщение можно редактировать, перенести в другую опубликованную губернию и удалить с подтверждением. Сообщения сохраняются как ограниченная структура JSON без пользовательского HTML; внешние ссылки допускаются только с `http://` или `https://`, внутренние — от корня сайта. При вставке форматированного текста с форумов CSS-цвета `rgb(r, g, b)` переводятся в безопасные шестнадцатеричные цвета; переносы строк и допустимое начертание сохраняются. Произвольные CSS-свойства по-прежнему не принимаются.

На странице губернии ссылка «← Вернуться к карте» находится над заголовком. При прокрутке длинных сообщений она переходит в компактную панель у самой верхней кромки окна вместе с фильтрами справа; панель остаётся непрозрачной, без просвета для текста. Пока исходные фильтры видны, их копия в закреплённой панели не показывается. Отдельная кнопка ↑ появляется в правом нижнем углу после ухода карты за верх окна и плавно возвращает к карте губернии.

Фильтры по уезду, населённому пункту и году вместе со сбросом остаются доступны при прокрутке сообщений: исходная форма сохраняется под картой, а закреплённая использует то же состояние и умещается на широком и узком экране. Переходы из списка заголовков учитывают высоту закреплённой панели, чтобы не скрывать название сообщения.

У сообщения есть обязательная категория и губерния (по умолчанию открытая), необязательные уезд, населённый пункт, год и архивный шифр. Списки уездов зависят от выбранной губернии и показываются после загрузки её исторического GeoJSON; населённые пункты — от губернии и уезда. Если снять оба ограничения, доступны пункты всех опубликованных губерний: выбор пункта заполняет губернию и его уезд. При ручном выборе другого уезда несовместимый населённый пункт сбрасывается. На странице губернии под картой доступны фильтры по уезду, населённому пункту и году; они вместе ограничивают сообщения и ссылки на них, не меняя порядок от новых к старым. Сброс возвращает все сообщения.

Администратор раскрывает соседнюю форму «Новый населённый пункт», вводит название, опубликованную губернию (изначально открытую), уезд, тип из списка «Настройки», URL страницы вида `/naselennyy-punkt/<slug>` (латинские строчные буквы, цифры и одиночные дефисы) и координаты в формате `широта, долгота`, например `54.25, 37.6`. URL обязателен и уникален среди всех пунктов; координаты проверяются по историческому полигону выбранного уезда. Пункт сохраняется в массиве `settlements` того же `data/gubernia-publications.json`. Старые пункты без URL получают стабильный адрес `/naselennyy-punkt/<id>` при чтении. Страница пункта показывает его название, губернию, уезд, тип (если он указан) и координаты; неизвестные или принадлежащие неопубликованной губернии пункты не доступны. Точки и подписи на карте губернии скрыты на общем виде и появляются только при крупном масштабе либо после выбора уезда/пункта. Нажатие на точку или её название открывает страницу населённого пункта; оно не включает фильтр сообщений. Фильтр по пункту по-прежнему доступен в форме под картой. Нажатие на полигон уезда выбирает фильтр уезда. Значок центровки над списком уездов либо кнопка «Сбросить фильтры» возвращает общий вид. Создание пунктов и изменение сообщений разрешены только администратору; посетители читают опубликованные записи и видят точки при достаточном приближении. Маршрут `POST /api/gubernias/[id]/settlements` сохраняет пункт, `POST /api/gubernias/[id]/posts` и `PATCH`/`DELETE /api/gubernias/[id]/posts/[postId]` обслуживают публикации. Старые файлы без `settlements` и `posts` читаются как пустые списки; старые сообщения без новых полей остаются доступными с пустыми метаданными. При удалении страницы губернии её сообщения и пункты тоже удаляются. Для большого публичного архива файловое хранилище без пагинации не подходит.

На `/naselennyy-punkt/[slug]` под географическими сведениями размещена справка о пункте: посетители читают её, администратор редактирует тем же TipTap-редактором, что и раздел «О проекте». Справка хранится отдельно от публикаций в `data/settlement-references.json` (путь можно переопределить через `SETTLEMENT_REFERENCE_PATH`), ключ — стабильный ID пункта; защищённый `PATCH /api/naselennyy-punkt/[slug]/reference` принимает проверенный документ. Ниже показаны только сообщения, привязанные к этому пункту: слева список заголовков с переходами к записям, справа — тексты и метаданные. Администратор может раскрыть «Новое сообщение», где нужные губерния, уезд и пункт уже выбраны, а также редактировать и удалять записи. Созданные здесь сообщения видны и на странице губернии; указанное в сообщении губернии название пункта ведёт на его страницу. Справка и сообщения не доступны через страницу неопубликованной губернии.

В карточке пункта администратору доступны обе формы: «Новое сообщение» с выбранным текущим пунктом и «Новый населённый пункт» с выбранной текущей губернией. Вторая использует ту же форму, что на странице губернии.

Кнопка администратора «Редактировать населённый пункт» открывает редактор справочных сведений (не меняет название, тип или координаты). Рядом «Удалить населённый пункт» запрашивает подтверждение и вызывает защищённый `DELETE /api/gubernias/[id]/settlements/[settlementId]`. Удаляются пункт и его справка; связанные сообщения сохраняются на странице губернии без привязки к удалённому пункту. После удаления открывается карта, с которой пришёл администратор.

Во время чтения сообщений в закреплённой колонке ссылка «← Вернуться к карте» появляется слева от выпадающего выбора года, только после ухода шапки страницы вверх. Видимой подписи «Год» нет; доступное имя поля — «Фильтр по году». Ниже находятся «Сбросить фильтр» и «Содержание» со ссылками на сообщения. Выбор года одновременно ограничивает статьи и оглавление; записи без года видны при выборе «Все годы». На узком экране эта строка, сброс и заголовок оглавления закрепляются у верхней кромки, а список заголовков прокручивается отдельно.

Исходная ссылка «← Вернуться к карте» находится над названием пункта. Между шапкой и колонкой сообщений при прокрутке появляется отдельная компактная кнопка; как только видна закреплённая колонка, она скрывается, не дублируя кнопку слева от года. Если пункт открыт с главной карты населённых пунктов или её списка, ссылка ведёт на `/?view=settlements`; если с карты губернии — к карте этой губернии (`/guberniya/[slug]#province-map`). При прямом открытии страницы без указания источника ссылка ведёт на главную.

## О проекте

На `/o-proekte` ссылка «← Вернуться к карте» расположена над заголовком. Текст раздела доступен всем; администратор меняет его кнопкой «Редактировать» в том же редакторе TipTap, что и сообщения губерний, но без заголовка и географических полей. «Отмена» не публикует черновик, «Сохранить» отправляет проверенный документ на защищённый `PATCH /api/about-content`. Опубликованный текст хранится в `data/about-content.json` (игнорируется Git); для изолированного окружения путь меняется переменной `ABOUT_CONTENT_PATH`. До первого изменения отображается исходное описание проекта.

Ссылки на [Sablin et al.](https://doi.org/10.11588/DATA/10064), [Kessler и Markevich](https://doi.org/10.34894/NQOASN) и подпись со ссылкой на [Веру Ирвин](https://t.me/verairvin) находятся в постоянном блоке под текстом. Ссылка «Данные RiStat ↗» расположена на отдельной строке, чтобы не разбиваться переносом после библиографического описания. Эти данные нельзя изменить из редактора.

Источники сгруппированы в две пронумерованные строки: авторы, название набора и ссылка отделены типографически, без перегородок между строками; единственная линия отделяет весь блок от основного текста раздела. Под ними сразу следует подпись «Концепция, дизайн и разработка сервиса — Вера Ирвин», без отдельного ярлыка. Подпись набрана тем же размером, что и вступление, полужирно; названия наборов — обычным начертанием. Над заголовком каждой страницы губернии повторяется надзаголовок портала, как на странице «О проекте».

## Настройки

После входа администратора в шапке главной между «О проекте» и «Метрики» появляется ссылка «Настройки» (`/nastroyki`). Прямое открытие страницы без действующей сессии возвращает 404. Страница ведёт два списка: категории сообщений и типы населённых пунктов. Формы публикации сообщений и создания населённых пунктов берут значения из этих списков, поэтому добавленное название доступно в формах после обновления страницы. Каждое название можно переименовать прямо в строке (Enter — сохранить, Escape — отменить) или удалить после подтверждения; переименование сохраняет место в списке, удалить можно любое название, включая исходные. Правки меняют только варианты для будущих материалов: уже созданные сообщения и населённые пункты остаются историческими снимками, их данные не перезаписываются, а прежнее название продолжает отображаться. При редактировании сообщения без смены категории прежнее значение принимается даже после переименования или удаления, а другая категория должна быть в текущем списке.

Изменения сохраняются в `data/site-settings.json` (игнорируется Git, создаётся при первом изменении; путь переопределяется переменной `SITE_SETTINGS_PATH`) атомарной заменой файла; записи выполняются по очереди. Пока файл не создан, действуют исходные значения — категории «Статья», «Персона», «Ссылка на источник», «Источник с индексацией» и типы «Город», «Село», «Деревня»; их тоже можно переименовывать и удалять, а первая успешная правка создаёт файл. После этого файл остаётся единственным источником списка: удаление всех названий сохраняет пустой список, исходные значения не возвращаются. Защищённые `POST /api/nastroyki` (`{ kind, name }`), `PATCH /api/nastroyki` (`{ kind, originalName, name }`) и `DELETE /api/nastroyki` (`{ kind, name }`) требуют входа администратора, где `kind` — `categories` или `settlementTypes`, и возвращают обновлённые списки. Названия нормализуются (обрезка и сжатие пробелов) и ограничены 80 символами; исходное название при переименовании и удалении ищется по точному совпадению, дубликаты, отсутствующие названия и переполнение отклоняются с кодом 400.

## Метрики

После входа администратора в шапке главной появляется ссылка «Метрики» (`/metriki`) — сразу после «Настройки». Прямое открытие страницы без действующей сессии возвращает 404. Страница показывает актуальные показатели **содержимого портала**: количество опубликованных и неопубликованных губерний, сообщений и населённых пунктов в опубликованных губерниях; ниже — те же показатели по каждой опубликованной губернии со ссылками на её страницу. Данные рассчитываются за одно чтение состояния публикаций, без отдельной копии статистики. Посещения пользователей не отслеживаются, поэтому статистики трафика на странице нет.

## Карта

`components/GuberniasMap.tsx` вычисляет начальный bounding box текущих опубликованных губерний и задаёт вид через `fitBounds` с адаптивными полями. Кнопка «Вся империя» показывает все 76 губерний; счётчик доступных обновляется после публикации и удаления. Минимальный масштаб каждого режима вычисляется вокруг его обзора: после предельного отдаления колесо, жест масштабирования и кнопка «+» снова приближают к соответствующей области, а не к пустому морю. Ниже масштаба обзора колесо и жест используют центр карты как точку приближения; на обычных уровнях MapLibre снова приближает к курсору. `GET /api/gubernias` совмещает локальную геометрию с состоянием публикаций; MapLibre получает GeoJSON без vector tiles. В `addGuberniaSourceAndLayers` находятся локальные источники и слои `gubernias-fill`, `gubernias-border`, `gubernias-labels`, `gubernias-published-labels`, бежевое выделение опубликованных губерний и нейтральный исторический контекст.

На главной крупные переключатели «Губернии» и «Населенные пункты» используют одну карту MapLibre. Режим губерний сохраняет исходные границы, подписи и список доступных губерний. Режим пунктов открывается **в том же начальном масштабе и с теми же полями**, что и обзор доступных губерний. При первом переключении он загружает локальные файлы `public/data/uyezds-1897/<id>.geojson` для всех 76 губерний: контуры губерний и границы уездов в этом режиме взяты из одной реконструкции RiStat 1897 года; опубликованные губернии бежевые, остальные нейтральные. В отдельном источнике `uyezds-1897-province-label-points` — по одной внутренней точке подписи на каждую из 76 губерний RiStat. Их названия показываются сразу приглушённым полупрозрачным шрифтом; подписи уездов на главной карте отсутствуют. Слои пунктов имеют приоритет над названиями губерний при пересечении. В режиме «Губернии» подписи этой реконструкции скрыты. Линии RiStat могут немного отличаться от контура главного режима (другая реконструкция Sablin и др.); геометрии двух реконструкций не склеиваются. Отдельный точечный GeoJSON-источник получает населённые пункты только опубликованных губерний из `getPublishedGeoData()`; подписи точек появляются при приближении. Слева находится список «НАСЕЛЁННЫЕ ПУНКТЫ»: наведение синхронно выделяет строку и точку, клик открывает локальную страницу пункта. Администратор создаёт пункт через «+ Добавить населённый пункт» в этом списке — открывается та же форма `SettlementEditor`, что и на странице губернии; после сохранения обновляются список и точки. При отсутствии пунктов карта остаётся доступна и показывает сообщение в списке.

Кнопка обзора в левом нижнем углу действует в обоих режимах: «Вся империя» показывает 76 губерний, «N доступных губерний» возвращает масштаб к опубликованным территориям. Число N берётся из текущего списка опубликованных губерний. Каждый режим запоминает собственный выбор обзора при переключении вкладок; ограничение минимального зума и приближение обратно к целевой области следуют выбранному обзору.

Окно «Населённые пункты» подстраивает ширину под самое длинное название в списке, но не может быть уже однострочного заголовка «НАСЕЛЁННЫЕ ПУНКТЫ». Между заголовком и строками расположен поиск по названию: он без учёта регистра фильтрует только список, не скрывая точек на карте; пустой запрос показывает все пункты, отсутствие совпадений обозначается отдельным сообщением. Кнопка создания у администратора остаётся доступной при любом запросе. Кнопки центровки в этом окне больше нет — обзор переключается нижней кнопкой карты. На узком экране окно ограничено доступной шириной карты, а список при необходимости прокручивается.

В режиме «Губернии» названия центрируются MapLibre на точках `labelCoordinates` и на карте показываются одним словом без переноса. Все подписи губерний имеют одинаковый размер шрифта, заданный `LABEL_TEXT_SIZE` в `components/GuberniasMap.tsx`. На обзоре доступных губерний названия видны сразу; длинное название может выходить за границу своей губернии. Нейтральные подписи показываются согласно `labelMinZoom`, чтобы не перегружать обзор всей империи. Плавающий список располагается поверх карты и использует то же hover-состояние: наведение на название выделяет полигон, наведение на полигон выделяет строку. Клик в любом представлении открывает `/guberniya/[slug]`.

`components/UyezdsMap.tsx` загружает только файл открытой губернии и показывает её контур, границы уездов/округов, подписи и сохранённые точки MapLibre без современной подложки. Для каждого уезда `lib/district-labels.ts` выбирает внутреннюю точку крупнейшего полигона; отдельный точечный GeoJSON-источник подписей даёт ровно одну надпись на уезд даже при сильном приближении и не меняет исторические границы. Широкая на компьютере карта расположена **под** названием губернии; её высота адаптируется к экрану, на телефоне она выше. Слева поверх карты список единиц с заголовком «ДОСТУПНЫЕ УЕЗДЫ»: наведение в списке выделяет полигон, наведение на полигон — строку; нажатие выбирает фильтр уезда и приближает карту, повторное нажатие на выбранный уезд снимает фильтр и возвращает общий вид. Значок центровки в панели также показывает всю губернию и сбрасывает выбор. Километровой шкалы и строки источника под картой нет; страницы уездов и переходы на них не создаются. Связь карты, фильтров и сообщений на странице организована в `app/guberniya/[slug]/ProvinceExplorer.tsx`.

`public/logo-gold.png` — предоставленная автором золотая монограмма на прозрачном фоне в шапке; отдельный тёмный `public/favicon-dark.png` используется для значка вкладки. Авторизация: `components/AdminAccess.tsx`, серверная проверка и cookie в `lib/admin-session.ts`, обработчик `app/api/admin/session/route.ts`. Атрибуция исторического источника сохранена здесь и на странице «О проекте».

Когда понадобятся vector tiles, слой данных и конфигурация слоёв изолированы в `addGuberniaSourceAndLayers`; текущий прототип использует локальные GeoJSON.
